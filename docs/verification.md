# Проверки реализации

В Linux-среде разработки выполнены:

- `npm run build`: TypeScript и production-сборка Vite проходят.
- `cargo test --manifest-path src-tauri/Cargo.toml --lib --no-default-features --locked`: **30 тестов проходят**. Проверяются границы слова активации, таймаут, маршрутизация команд, числа словами для громкости, настройки, HTTP-протоколы LM Studio/Ollama, отмена генерации и отсутствие вставки устаревшего текста.
- `cargo clippy --manifest-path src-tauri/Cargo.toml --lib --no-default-features -- -D warnings`: проходит без предупреждений.
- `cargo fmt --manifest-path src-tauri/Cargo.toml --check`: проходит.
- Проверка типов для `x86_64-pc-windows-msvc`: Windows API, CPAL, трей, глобальная клавиша и IPC Tauri компилируются. Для этой проверки использована временная копия с `tauri::test::mock_context` вместо генерации ресурсов приложения; упаковку и установщик она не проверяет.
- Chromium: вкладки интерфейса, примеры команд, явный режим предпросмотра, переключение провайдеров, поля Whisper, минимальная ширина 760 px. Ошибок JavaScript и горизонтального переполнения нет.
- Chromium с тестовым IPC: успех/ошибка переключения микрофона, перечисление устройств, сохранение настроек, список моделей и вывод результата. Это проверяет интерфейс и контракт IPC; Windows API в этих сценариях заменён заглушкой.
- `cargo run --manifest-path src-tauri/Cargo.toml --example check_llm --no-default-features --locked`: получен ответ о IPv6 от реального LM Studio на `http://198.18.0.1:1234`, модель `google/gemma-3-4b`.

Нативный запуск Windows с микрофоном, SAPI, медиасессиями и вставкой в приложения в этой среде недоступен. Автовоспроизведение на Яндекс Музыке/Spotify и YouTube также не проверялось с аккаунтом пользователя. Для этих функций предусмотрен [отдельный список приёмочных сценариев](windows-checklist.md).

Windows CI выполняет полную сборку приложения и установщика NSIS. Конфигурация CI добавлена в репозиторий; запуск workflow и получение установщика на удалённом Windows runner в рамках этой сессии не выполнялись.

## Установка без инструментов разработки

Добавлены ресурсы Vosk и модели в NSIS, offline WebView2 installer, статический CRT, мастер первого запуска и tag-triggered GitHub Releases workflow. SHA256 скачанных архивов проверен при подготовке; комплект содержит четыре DLL и распакованную модель. Первый запуск проверен в Chromium с тестовым IPC: выбор устройства, сигнал, ошибка доступа и завершение мастера. Проверка типов Windows/Tauri с тестовым контекстом прошла после этих изменений.

Реальный NSIS и установленная копия в этой Linux-сессии не запускались. Release workflow выполняет эту проверку перед публикацией, но запуск workflow требует отправленного тега в GitHub; удалённый релиз в этой сессии не создавался. Проверка CI не заменяет ручные испытания микрофона на чистой Windows 10/11.

## Исправление пути Vosk в 0.2.2

Tauri canonicalize возвращает в Windows путь с префиксом `\\?\`. Старые narrow C API Vosk могут не открыть модель по такому пути, хотя Rust успешно проверяет существование папки. Перед native-вызовом добавлена совместимая канонизация через dunce, а установленная самопроверка теперь воспроизводит канонический путь GUI. Добавлен Windows regression test; в Linux-среде выполнена проверка компиляции Windows-тестов, но запуск их по-прежнему выполняется на Windows runner. Улучшены ошибки для неверной папки, отсутствующего/пустого файла конфигурации. Версия 0.2.2 проверена локальными тестами и сборкой интерфейса; публикация/проверка реальной установленной копии требуют Windows CI.

## Доработки 0.3.0

- Проверены новые сценарии Rust: совместимость старых настроек, приоритет точных команд/шаблонов, выключение и блокировка правил, native URI с кириллицей/`&`/`#`, валидация JSON-намерений модели, HTTP-форматы structured output LM Studio/Ollama. Интеграционный тест проводит неизвестную фразу через HTTP → разбор → медиадействие, а ответ модели сохраняет без вставки. Отключённый fallback и неверная известная команда не обращаются к модели.
- В реальном LM Studio `http://198.18.0.1:1234`, `google/gemma-3-4b`: «Пожалуйста, останови воспроизведение» → Pause; «Расскажи, что такое IPv6, в двух предложениях» → Answer. Проверочный example `resolve_command` печатает намерение и не выполняет действие ОС.
- Chromium с тестовым IPC: создание/сохранение/повторное открытие шаблона и override, переключение enabled, ошибка сохранения без ложного успеха, сохранение настроек музыки/LLM без потери правил, ширина 760 px, вывод ответа. Overlay отдельно проверен на прозрачность, состояния прослушивания/LLM/ответа и отсутствие invoke команд ОС. Снимки просмотрены.
- DOM-адаптер музыки проверен на искусственной странице: поиск кнопки в native-совместимом контейнере, выбор вкладки «Треки», один клик и отсутствие ложного успеха, когда продолжает играть предыдущая композиция. Это не проверка реального аккаунта Яндекс Музыки.
- Протокол официального Windows-клиента Яндекс Музыки (`yandexmusic://` с преобразованием пути внутри приложения) и селекторы сверены статически с клиентом 5.69.1. Приложение в Linux не запускалось, проприетарные файлы в репозиторий не включены.

Ограничения: полный NSIS, показ прозрачного окна без перехвата фокуса на Windows, микрофон, SAPI и фактическое native-воспроизведение требуют Windows-приёмки. Spotify реализован как native-поиск с ручным выбором результата. При уже запущенном клиенте Яндекса CDP может быть недоступен; тогда открывается поиск в приложении с явным сообщением. Выпуск 0.3.0 в GitHub в этой сессии не публиковался.
