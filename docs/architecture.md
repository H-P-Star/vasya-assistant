# Архитектура

```
CPAL / WASAPI → mono PCM 16 kHz → Vosk → Gate → очередь действий
                                                        ↓
                                      [Whisper, опционально]
                                                        ↓
                                                  Router / aliases
                                                        ↓
                 Windows API ← исполнитель → браузер / LM Studio / Ollama
                                      ↓
                                события Tauri → UI
```

`activation.rs` — независимый автомат: ожидание → активация → одна команда → ожидание. Голосовая активация проверяет границу слова и начало фразы; упоминание имени в середине команды не активирует помощника. Активация истекает по таймауту.

`audio.rs` — фоновый поток CPAL/Vosk и отдельная явная сессия калибровки. Захват для калибровки получает эксклюзивный busy-guard, закрывает фоновый поток и не передаёт фразы исполнителю. Никаких обращений к UI из real-time callback напрямую нет: события Tauri передаются через потокобезопасный sink. Очередь аудио ограничена; потеря блока инвалидирует текущую фразу. Между режимами и при mute поток закрывается. Аудио используется в памяти, максимум 30 секунд на фразу.

`calibration.rs` — уровни шума/сигнала, клиппинг, рекомендованное усиление и словарь исправлений. `voice.rs` — запуск внешнего Piper с фиксированными аргументами, временный PCM WAV и отдельное усиление голоса. `credentials.rs` — ключи провайдеров под Windows DPAPI, отдельно от settings.json.

`speech.rs` — небольшой FFI-адаптер к официальному `vosk_api.h`. Библиотека загружается динамически, её время жизни больше времени жизни model/recognizer. Оба handle освобождаются в `Drop`. Whisper запускается отдельным локальным процессом без shell; временный WAV и результат изолированы в временной папке.

`runtime.rs` — один исполнитель действий, ограниченная очередь, сериализация браузерных операций и SAPI. Микрофон при выполнении команды закрывается, чтобы помощник не реагировал на собственную речь. Изменения mute, настроек и остановка повышают epoch: устаревшая диктовка/генерация не вставляется. Результат сохраняется в UI до попытки вставки. Для неизвестной фразы `generator::resolve` получает от LLM JSON-намерение и проверяет его по закрытому списку действий. Ответ модели сам по себе не вставляется. Произвольные пути, процессы, shell и JavaScript модели недоступны. Неверная известная команда (например, громкость 999) отклоняется без LLM.

`platform.rs` — только Windows: Unicode SendInput, foreground HWND/PID, SAPI, Core Audio, GSMTC. Вставка не использует clipboard. Проверка активного HWND выполняется перед каждым пакетом ввода. Интерфейс `Platform` позволяет проверять отмену и результат с заглушкой ОС.

`browser.rs` — кодирование поисковых URL, извлечение videoRenderer из публичной выдачи YouTube, `MusicService` и адаптеры установленного приложения и браузера через CDP. Яндекс Музыка получает deeplink с экранированными параметрами; CDP подключается к процессу, запущенному Васей на loopback-порту, либо восстанавливает сохранённое подключение после проверки native-окна. Запрос разбирается на трек/исполнителя, кандидаты ранжируются, результат проверяется по metadata и playing-state. Подготовка клиента перезапускает только процессы с выбранным точным путём .exe и запускается отдельной явной кнопкой. Нативное приложение не закрывается при выходе помощника. Spotify получает native search URI, без гарантии автозапуска. Браузер запускается с отдельным user-data-dir и случайным loopback-портом; команды JavaScript фиксированы, распознанный текст не интерполируется в исполняемый код.

`desktop.rs` — Tauri IPC, трей, один экземпляр, горячая клавиша, загрузка/сохранение настроек. UI не имеет произвольного доступа к файловой системе, shell или HTTP. Разрешения собственных команд генерируются `AppManifest::commands` и выдаются только локальному окну `main`. Окно `island` имеет подписку на события и узкие команды закрытия, раскрытия карточки, копирования текущего результата и открытия главного окна; `island.rs` управляет его положением, видимостью и задержкой скрытия без захвата фокуса. Удалённые страницы в окна не загружаются. Запросы к сервисам делает Rust.

`src/main.ts` — состояние окна, настройки, журнал в памяти, редактирование результата и GUI-редактор `aliases` и `builtin_overrides` (точные правила и шаблоны с `{query}`). Каталог встроенных правил — источник runtime-маршрутизации и редактора. `src/calibration-ui.ts` ведёт мастер калибровки; запись и распознавание выполняет Rust. `src/island.ts` — отдельная ветка интерфейса для прозрачной интерактивной панели. Она не вызывает команды распознавания, настройки, произвольные процессы или HTTP. При запуске вне Tauri явно отображается предпросмотр, вызовы ОС не имитируются.

Расширение: добавьте вариант в `Command`, разбор фразы и ветку исполнителя. Новый движок ASR должен выдавать те же фразы и PCM-пакеты; новый музыкальный сервис — реализовать `MusicService` и подключиться к выбору провайдера. Нативные плагины и произвольное исполнение команд из JSON не включены.

Whisper входит в установщик с многоязычной base-моделью. Две CPU-сборки создаются из зафиксированных исходников со статическим CRT; подходящая выбирается по CPU-флагам. Язык, подсказка словаря и персональные исправления применяются к активированной фразе. Короткие команды паузы/громкости/диктовки выполняются непосредственно по Vosk. Для вызова Vosk создаёт второй recognizer с ограниченной грамматикой на той же модели; короткая подтверждённая активация не становится неизвестным запросом к LLM.

LM Studio, Ollama, OpenRouter, OpenAI и совместимые API используют общий отменяемый запрос. API base может уже содержать `/v1`; он не дублируется. Bearer-ключ читается в Rust. Structured output опционален, но любое действие независимо проверяется по закрытому списку. OpenAI использует `max_completion_tokens`; локальные и совместимые chat API — `max_tokens`.
